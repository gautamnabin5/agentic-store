Agentic-Native Patterns (built AI-first from day one)

What "agentic-native" means

Instead of adding an agent on top of a REST API, you design the system around the agent from the start. The LLM + tools layer IS the primary interface — not an afterthought layered over a human-facing API. Think Cursor, Claude Code, Linear's AI intake.

Retrofitting (what you're doing)

  • REST API built for humans first
  • Agent wraps it after the fact
  • Tools mirror existing endpoints
  • Auth designed for browser sessions
  • State lives in DB, agent is stateless
  • Hard to change DB schema for agent needs

Agentic-native

  • Tools are the primary API contract
  • Schema designed for agent context (fewer joins, denormalized reads)
  • Auth designed for agent sessions (e.g. short-lived tool tokens)
  • State can live in the agent context window
  • Streaming is a first-class requirement
  • No UI required — agent IS the UX
Native Pattern

Tool-First Design

You design your system's capabilities as tools before building any UI. The tool schema IS the API contract. Vercel AI SDK, LlamaIndex, and Anthropic's tool use all push this model.

No REST layer. Tools ARE the API:

createOrder(items[])
searchProducts(query, filters)
getUserHistory(limit)
trackShipment(orderId)

the agent does — via a shared SDK.

Agent-as-Backend

The LLM agent IS the backend. No traditional REST layer — the frontend sends messages, the agent decides what to do and calls internal functions. State is managed in conversation history + a lightweight store. Used by startups going fast.

Structured Output / Form-free UX

Instead of forms, the user describes what they want in natural language. The agent uses structured output (JSON mode) to extract typed data, then presents it back for confirmation before acting. The "form" emerges from the conversation.

User: "2 of the blue widget and 1 red one"
  ↓ LLM extracts
{items: [{id:"blue-widget",qty:2},
         {id:"red-widget",qty:1}]}
  ↓ agent confirms
"Place this order? Total: $47.00"
  ↓ user: "yes"

Native Pattern

Human-in-the-Loop (HITL)

Agent pauses before irreversible actions and asks for explicit human approval. Not just "are you sure?" — the agent presents a structured summary of what it's about to do. Critical for destructive or financial actions like placing orders.

Agent plans: placeOrder([...])
  ↓ PAUSE — irreversible
Agent: "About to place:
 • Blue Widget x2 — $18.00
 • Red Widget x1 — $29.00
 Total: $47.00. Confirm?"
  ↓ user: "yes"
placeOrder(items) ← executes
